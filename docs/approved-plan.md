# EchoEar「山海司天」实施约定

2026-10-08，用户确认第一阶段与第二阶段顺序，并在浏览器查看画面后明确要求「好的，继续推进开发」。视觉方案已确认，进入固件开发。

## 目标

EchoEar v1.2 / ESP32-S3 / 16 MB Flash 与 PSRAM / 360×360 ST77916 + CST816S。

固定本机 ESP-IDF `release/v6.1` 提交 `9a97f6c54ec638111ce55cd36581b3c192f15207`，允许 `master` 作为备选。日文界面、东京天气；Codex、Antigravity、Claude Code、Cursor 额度先模拟。

## 第一阶段

- 主页、天气详情、额度总览、服务详情、待机五类页面，以附件玄青鎏金、神兽、山水构图为视觉依据。
- 背景与图标分离，文字和有效额度环动态合成；保持圆屏安全区与原尺寸可读性。
- 五类 PNG、对比总览、离线交互 HTML；同时展示 Wi-Fi 设置、忘记确认、配网二维码、错误和天气缺失状态。
- 用户确认后冻结素材、布局与字体，供预览和固件共用。

## 第二阶段

- 官方 BSP + LVGL + network_provisioning，记录组件锁及实际构建配置。
- BLE 扫码配网，设备独立 PoP；结束后仍能重新配网，配网期间不自动待机。
- 设备提供断开、重连和忘记网络；断开保留设置并暂停重连，重启自动连接；忘记经确认，只清除 Wi-Fi 配置。
- 东京天气 HTTPS 获取，连接即刷新、15 分钟定期刷新，SNTP 日本时间。失败保留旧数据并标记；无数据显示 `--`。
- 网络和天气事件交回 UI 线程，局部更新数值；未知额度上限只显示余额，AI 页面标注「デモ値」。

## 验收

浏览器字体/边界/碰撞与交互、最小实际 C 逻辑检查、固定 SDK 原生构建与资源预算。备份原厂 Flash/NVS 后实板检查配网循环、触摸、待机、恢复及至少 30 分钟联网和切页混合负载；交付时区分源码、主机检查、构建、烧录和实板结果。

首版为独立显示器 Demo。日历、语音、摄像头、真实额度采集和 OTA 留到后续；R1 保留为参考。
