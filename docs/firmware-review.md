# Native firmware review

2026-10-08. Read-only source review after the gesture, provisioning-log, HTTP, USB snapshot and diagnostic-stack changes. Latest status: final hardware verification must be rerun.

What this change does: It runs the approved five-page UI on EchoEar, connects to saved Wi-Fi or BLE provisioning, and shows real Tokyo weather and JST time. AI quotas remain demo values; the USB console is privileged local diagnostic access.

**Verdict: Await the corrected firmware's hardware regression and complete 30-minute run. The earlier static review did not detect the diagnostic task's real stack overflow; its previous conditional ship statement is withdrawn. The latest source/interface changes are consistent, but increasing the stack to 8192 bytes is not proof of sufficient runtime headroom.**

## Hardware finding awaiting final verification

**P1 — The 4096-byte `sh_console` stack overflowed during actual framebuffer capture.** This was found by the root task on the device, after the initial source review. `main/main.c:90` now allocates 8192 bytes, and `SH_STATUS` reports the console's minimum remaining stack via `uxTaskGetStackHighWaterMark(NULL)`. That API's unit is bytes in the fixed ESP-IDF version. The corrected firmware still needs the repeated page/CRC captures, BLE regression and complete mixed-load run with minimum measured console headroom above 512 bytes and no fatal error or extra reset. No successful hardware outcome is inferred from the source change.

## Findings resolved during review

1. **P1 — Swipe events were discarded; swipe release could wake standby.** `main/sh_ui.c:242-265` now removes `LV_OBJ_FLAG_GESTURE_BUBBLE` from the screen and calls `lv_indev_wait_release()` when it accepts a horizontal swipe. In LVGL 9.4.0, leaving the bubble flag on the screen makes the input handler climb to a null parent; leaving the finger active on the persistent screen permits a later `CLICKED` event. Both cases are addressed by the applied changes.

2. **P1 — The fixed SDK logged provisioning session keys at INFO.** `main/sh_network.c:492-494` now limits the `security1` tag to WARN before BLE starts. The exact SDK source's `hexdump()` logs at INFO, including the shared session key. The application also keeps `network_prov_mgr` at INFO so its DEBUG password-fragment messages stay disabled. No vendor source was changed.

3. **P2 — The original HTTP reader could keep receiving after its outer deadline and after a connection changed.** `main/sh_network.c:299-367` now checks the budget, connection generation and 8 KB cap in the HTTP collector and between async calls. On a violation it shuts down that request's socket in the weather worker; the same worker then cleans up the client. The collector checks bounds before copying, leaves the body space for its terminator, and cannot free the HTTP client from inside its callback. The remaining timeout scope is described below.

## What was checked

- Read `main.c`, UI, network, weather parser, model and their public callers/headers, plus the relevant locked LVGL, provisioning and SDK implementations. SDK: `release/v6.1` commit `9a97f6c54ec638111ce55cd36581b3c192f15207`; target ESP32-S3; BSP 1.1.0, LVGL 9.4.0, network_provisioning 1.3.1. The inspected SDK log/protocomm/HTTP/transport files are unmodified.
- UI objects are deleted before their external ring pixel buffers are freed. Failed ring allocation leaves an empty binding that refresh skips. LVGL marks deleted event targets and resets active input objects, so cleaning children in a click handler does not leave that handler using the removed child. QR buffers belong to the QR widget and are destroyed with it. UI and console mutations use the BSP display lock.
- The network snapshot and request generation use one mutex; HTTP operations do not hold it while waiting for transport. Saved Wi-Fi configuration is owned by the connection worker, and its actions use a bounded queue. Normal cancellation/failure stops provisioning and restores the saved configuration; explicit forget replaces only Wi-Fi configuration. Startup does not erase NVS on an initialization error. Pairing has a two-minute deadline; the QR is cleared on stop and active pairing/overlays pause standby. Late weather results cannot overwrite a newer network generation.
- Weather parsing rejects malformed/truncated/trailing JSON, wrong field shapes, out-of-range numbers and unsupported WMO codes. Failure preserves the previous complete reading and marks it stale. Model and weather tests passed with AddressSanitizer and UndefinedBehaviorSanitizer. The host build suppresses only macOS's deprecation warning for the unchanged cJSON dependency.
- Snapshot rendering finishes and releases the BSP lock before USB transmission. The snapshot buffer stays alive until transmission ends, then is destroyed. A CRC and sent-byte count let the receiver reject a truncated frame. All normal ESP logs acquire the serial mutex before their stdio output in the actual Log Version 1 configuration. The snapshot path takes locks in that same order; no display/serial lock cycle was found.
- The only caller and declaration of `sh_ui_snapshot(int *captured_page)` match. The page and RGB565 image are captured under the same BSP lock; the new six-field header is read by both Python receivers. The soak runner verifies the page and CRC for each capture, visits all five pages three times, and checks stack headroom. Wi-Fi's larger icon remains inside its existing hit area; the quota demo label is drawn after its new dark panel, above the unchanged provider hit areas. The shared layout and generated native scene agree.
- An additional P2 verification gap was found and corrected in `tools/device_soak.py`: successful captures previously dropped text read before/after the binary frame, and allowing one `rst:` line could miss a reset when the initial boot was absent. The runner now logs that surrounding text while skipping binary pixels, records a startup reset baseline, and rejects a later increase. Its `BaseException` path overwrites the result on an interrupted run instead of leaving an old PASS. A mock-only host check confirmed retained fatal/reset text, rejection of wrong page/CRC and rejection of a reset after startup; neither serial access nor image/file export was used. Both receivers pass Python syntax parsing.

## Limits of this approval

- The HTTP budget is ten seconds checked between SDK calls and at connection/header/data callbacks. It is **not** a hard ten-second wall-clock bound: DNS follows the SDK's finite retries, and an internal SDK read can overrun the outer budget before the next callback. A slowly dripped incomplete header can defer that callback. This can delay the isolated weather worker; it does not hold the display or snapshot lock. A strict wall-clock limit would need independent interruption of the blocking transport.
- The global diagnostic log mutex can pause other log-producing tasks during a USB snapshot. Chunk writes time out when the reader stops, and the BSP lock is already released. The console and screenshot protocol are local lab tools; they are not an external service.
- No reviewer hardware operations, exports, source/config edits, vendor changes, destructive NVS tests or injected allocation failures were performed. Only this review record was updated. The root task owns the actual build, CRC captures, physical touch checks, BLE cycles and 30-minute mixed-load run. Earlier device results do not validate the corrected diagnostic stack or latest shared layout. Final hardware regression and the complete 30-minute test remain pending and must use the corrected firmware and result-logging script.

Official API context was retrieved through Espressif Documentation MCP; exact fixed-version behavior was checked against the official SDK/component sources. Supplemental references: [HTTP client API](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/protocols/esp_http_client.html#functions), [provisioning options](https://docs.espressif.com/projects/esp-jumpstart/en/latest/esp32/networkconfig.html#configurable-options), [LVGL 9.4 source](https://github.com/lvgl/lvgl/tree/v9.4.0/src).

Known risks: diagnostic stack sizing still needs runtime proof, and the transport budget is checked at SDK callback/call boundaries, not enforced by an independent wall-clock watchdog.
